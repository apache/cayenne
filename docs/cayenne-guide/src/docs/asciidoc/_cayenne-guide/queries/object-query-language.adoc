==== Query Structure

[source]
----
[ select [ distinct ] columns ]
from Entity
[ where     expression ]
[ having    expression ]
[ order by  orderings ]
[ limit n [ offset m ] ]
[ prefetch  paths ]
----

The clauses must follow in this order, and all of them, except for `from`, are optional (even `select`!). Here are the
rules of the language:

* There is a single root entity, named in the `from` clause. All other entities are reached via the relationship paths
starting at the root (`paintingArray.toGallery.galleryName`), so there are no entity aliases and no explicit joins.
Just like in expressions, a join is made outer by appending `+` to a path component (`paintingArray+`), and a join
is split from the other joins over the same path with an alias (`paintingArray#p1`).
* Every `expression` above, as well as every column and ordering, follows the syntax of Cayenne
<<Expressions,expressions>>, the same one that `ExpressionFactory.exp(..)` takes. Anything that is valid in
an expression is valid in a query: comparisons, `like`, `in`, `between`, arithmetics, functions, `db:` paths, etc.
* The keywords are case-sensitive, and must be spelled exactly as shown here, which is also true for the expressions.
The words that start the clauses are not reserved, and can be used as property names. The only reserved word is
`self`, that denotes the root object. A property called "self" has to be written as `obj:self`.
* A query with no `select` clause, or the one with `select self`, fetches the root objects and is an `ObjectSelect`.
Any other `select` clause results in a `ColumnSelect`.
* There is no `group by` clause. Just like with the fluent `ColumnSelect`, when any of the columns is an aggregate
function, all the other columns become the grouping columns.
* Only selecting queries are supported. There is no `update` or `delete`.

==== Parameters

A parameter is a name prefixed with `$`, the same as in expressions. The values are passed to the `parse(..)` method
and are bound in the order in which the parameters first appear in the String. If the same name is used more than once,
it takes a single value that is bound in all those places. A value can be anything that is a valid expression operand:
a scalar, a collection for `in`, a persistent object to match a relationship, etc.:

[source,java,indent=0]
----
include::{java-examples}/ObjectSelectParsedTest.java[tags=params]
----

The parameters can be used anywhere in the expressions, including the nested selects. `limit` and `offset` only take
integer literals.

The last three are there to avoid the type casts. They throw an exception if the query is of a different kind,

The parser needs no mapping information, so the names of entities and properties, as well as the types of the columns,
are only checked when the query is executed.
