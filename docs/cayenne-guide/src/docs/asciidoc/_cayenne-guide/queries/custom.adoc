=== Custom Queries

If a user needs some extra functionality not addressed by the existing set of Cayenne queries, he can write his own.
The only requirement is to implement `org.apache.cayenne.query.Query` interface. Its type parameter is the type of
the rows the query selects, so that the query can be run with `ObjectContext.select(..)` and the other selecting
methods, as well as with `execute(..)`.

`Query` has a single abstract method, `resolve(EntityResolver)`, that turns the query into a `ResolvedQuery` - an
immutable description of the statements to run, from which Cayenne picks the DataNode, generates the SQL and reads the
results. A custom query builds its resolved form by delegating to a standard Cayenne query, e.g. an `ObjectSelect`
assembled from the custom query's own state:

----

A query is resolved every time it runs, so a custom query may change its state between the runs, and the standard
queries it delegates to do not need to be cached.
